1. QUÉ ES Y QUÉ NO ES UBICAFÉ
═══════════════════════════════════════════════════════════════════════

Concepto: "Ubicafé — El mapa del café de La Paz".
App de EXPLORACIÓN + INFORMACIÓN territorial basada en datos censados.

Descubre: cafeterías, tostadurías, marcas de café, productores/cafetales, tiendas de café,
puntos de venta, otros lugares, y estadísticas del sector.

FUERA DE ALCANCE (no generar, no insinuar, no placeholders):
Wi-Fi, pet friendly, reservas, delivery, menús, reviews/puntuaciones, login, registro,
perfiles de usuario, seguidores, likes, chat, carrito, notificaciones push, costos de servidor,
interfaz de encuestadores, ni ninguna función sin respaldo en el censo.
NO es un clon visual de Roasters, Starbucks ni ninguna app de café.
NO incluir pestaña "Perfil": no hay usuarios ni cuentas en esta app.

El usuario final solo consulta. La carga de datos ocurre por un sistema administrativo EXTERNO;
esta app es solo lectora. El diseño debe tolerar datos incompletos: muchos registros del censo
tienen campos vacíos y la UI nunca debe romperse ni inventar información.

5. MODELO DE DOMINIO
═══════════════════════════════════════════════════════════════════════

Regla central: la unidad primaria NO es "la cafetería" sino LA ENTIDAD con ROLES MÚLTIPLES.
Una misma entidad puede ser a la vez cafetería + marca + tostaduría + productor.

enum Rol { CAFETERIA, MARCA, TOSTADURIA, PRODUCTOR, TIENDA, OTRO }
  etiquetaCorta(): "Cafetería","Marca","Tostaduría","Productor","Tienda de café","Otros"
  icono(): vector 24dp correspondiente
  color(): token de la paleta (verde = principal, tierra = acento)

class Entidad {          // una fila de CLASIFICACIÓN
  id, nombre, direccion, macrodistrito, lat, lng, Set<Rol> roles, Rol rolPrincipal,
  String marcaAsociada,          // agrupa sucursales de una misma cadena
  String nota,                   // fuente / motivo, se muestra como cita de la ficha
  DetalleCafeteria, DetalleMarca, DetalleTostaderia, DetalleProductor  // pueden ser null
}

class Sucursal { String nombre; String macrodistrito; String direccion; double lat,lng;
                  String entidadId; }   // un punto de venta = una sucursal de una entidad/marca

class CafeVariedad { String variedad; String region; int altitud; String proceso;
                     String tostado; List<String> notas; String entidadId; }

class PrecioObservado {           // OBLIGATORIO: precio + presentación + FECHA
  String cafeId, presentacion;    // "250 g"
  double monto;                   // Bs.
  String fechaObservacion;        // "2026-09-12"  -> se formatea "12 de septiembre de 2026"
  String nota;                    // "Precio de referencia estimado · Censo 2026"
}

Precios: el JSON de ejemplo trae Bs. 15 — Bs. 95 como rango observado del censo.
NO mostrar nunca un precio sin su fecha al lado. Si no hay fecha, ocultar el bloque entero.

Macrodistritos: enum o lista cerrada con Centro, Sur, Cotahuma, Max Paredes, Periférica, Mallasa.
Regiones de origen de café (ficha, NO son macrodistritos urbanos): Caranavi, Yungas, Tarija.
No confundirlos: "macrodistrito" clasifica lugares en la ciudad; "región" clasifica el cultivo.

6. CAPA DE DATOS
═══════════════════════════════════════════════════════════════════════

- CargadorCenso: lee assets/censo_ubicafe.json UNA vez (singleton, en Application o lazy holder),
  cachea en memoria. Nunca parsear en el hilo UI.
- RepositorioDatos: fachada ESTÁTICA. Ninguna Activity/Fragment/Adapter accede al JSON ni a
  CargadorCenso directamente. TODAS las consultas de pantalla pasan por aquí.
  API mínima obligatoria:
    List<Entidad> obtenerEntidades(); List<Entidad> obtenerEntidadesPorRol(Rol);
    List<Entidad> obtenerEntidadesPorMacrodistrito(String);
    List<Entidad> obtenerEntidadesPorMarca(String);
    List<Sucursal> obtenerSucursalesDe(String entidadId);
    List<Entidad> buscarSucursalesDeMarca(String marca);
    List<CafeVariedad> obtenerVariedades(); List<CafeVariedad> obtenerVariedadesDe(String entidadId);
    Optional<PrecioObservado> obtenerPrecioDe(String cafeId);
    List<Entidad> obtenerDestacadasCercanas(double lat, double lng, int limite);
    ResultadoBusqueda buscar(String texto);
    Estadisticas obtenerEstadisticas();  // conteos por rol, por macrodistrito, rango de precios
  Búsqueda: normalizar con NFD + quitar diacríticos + minúsculas; comparar por nombre de entidad,
  nombre de marca, dirección, macrodistrito, barrio, variedad y nombre de productor.
  Devolver ResultadoBusqueda agrupado en secciones: CAFÉS, MARCAS, ESTABLECIMIENTOS,
  PRODUCTORES, TOSTADURÍAS. Con estaVacio() para el empty state.
- Todo List devuelto es una copia defensiva. Nada de estado global mutable.
- Cuando la app se conecte a un backend, solo se reescribe CargadorCenso; RepositorioDatos
  y las pantallas no cambian. Esto es un requisito de diseño, no una sugerencia.

     targets táctiles >=48dp, contraste AA sobre crema, texto de chips >=13sp.

11. ESTILO DE CÓDIGO
═══════════════════════════════════════════════════════════════════════

- Java, 4 espacios, UTF-8, sin emojis en el código.
- Nombres, clases, variables, ids, strings y comentarios en ESPAÑOL, minúsculas con guion bajo
  para recursos; PascalCase y camelCase para Java.
- Modelos con campos final e inmutables; sin setters; sin singletons mutables.
- Javadoc en las clases del modelo y en los métodos públicos del repositorio, explicando
  QUÉ hace y POR QUÉ. Comentarios solo donde hay una decisión no obvia; nunca

- Favorecer Colecciones: sin concatenar cadenas en bucles, sin parseo repetido de JSON,
  sin trabajo pesado en el hilo UI (parseo y agregados fuera de onCreate/onViewCreated).

  sin System.out.println, sin Log.d de depuración.
- viewBinding everywhere; nunca findViewById con cast si existe binding.
  (en Fragment, limpiar binding en onDestroyView)
- Todo string en strings.xml con placeholders %1$s / %1$d y plurals <plurals> para
  "1 punto de venta" / "N puntos de venta" y "1 café" / "N cafés".
